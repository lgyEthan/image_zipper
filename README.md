# Image Zipper

Windows와 Mac에서 실행하는 **오프라인 이미지·PDF 압축 프로그램**입니다. 여러 파일을 불러와 DPI 또는 최대 파일 용량을 기준으로 줄이고, 선택한 폴더에 개별 저장하거나 하나의 PDF로 병합합니다.

## 할 수 있는 일

- PNG, JPEG, HEIC/HEIF, TIFF, BMP, WebP, AVIF, PDF 불러오기. GIF/APNG, ICO, JPEG 2000, PPM 등 Pillow가 지원하는 추가 형식도 읽습니다.
- JPEG, PNG, WebP, AVIF, TIFF 출력. 기존 PDF는 PDF로 유지합니다.
- 파일·폴더 추가, 드래그 앤 드롭, 병합 순서 변경, 일괄 저장, 취소, 앱 안의 작업 기록.
- **DPI 지정**: 인쇄 크기를 유지하면서 픽셀을 실제로 줄입니다. DPI 메타데이터만 바꾸는 방식이 아닙니다.
- **용량 상한 지정**: 품질과 픽셀 수를 탐색하고 실제 인코딩한 바이트 수로 상한을 검사합니다.
- 선택 파일의 즉시 DPI·용량 추정, 가벼운 원본 미리보기, `결과 확인` 버튼으로 실측 용량·DPI·압축 후 비교.
- 이미지 여러 장과 여러 페이지 TIFF를 PDF로 병합. PDF 파일도 페이지 단위로 함께 넣을 수 있습니다.
- PDF 안의 **텍스트·벡터·페이지 크기를 유지**하면서 적합한 내부 이미지를 줄이고 스트림을 최적화합니다.
- EXIF 회전 보정, ICC 프로파일 보존, 알파 채널 지원, 동일 이름 충돌 방지, 원본 파일 보호.

네트워크 업로드·계정·서버는 사용하지 않습니다.

## 실행

### 데스크톱 실행 파일

[최신 버전 다운로드](https://github.com/lgyEthan/image_zipper/releases/latest)에서 OS에 맞는 ZIP을 받아 압축을 풀고 실행하세요. 설치할 Python은 필요 없습니다. 변경 사항은 [변경 기록](CHANGELOG.md)에 정리합니다.

| 플랫폼 | 다운로드 ZIP / 실행 파일 | 기준 |
|---|---|---|
| Windows x64 | `…Windows-x64.zip` → `ImageZipper/ImageZipper.exe` | Windows 10/11 x64, CI는 Windows Server 2025 |
| Mac Apple silicon | `…macOS-arm64-notarized.zip` → `ImageZipper.app` | macOS 15 이상, arm64 |
| Mac Intel | `…macOS-Intel-notarized.zip` → `ImageZipper.app` | macOS 15 이상, x86_64 |

폴더 안의 라이브러리까지 함께 있어야 합니다. Mac의 **`-notarized.zip` 배포본은 Developer ID 서명과 Apple 공증을 완료**했고, 공증 티켓을 앱에 포함합니다. ZIP을 다시 푼 앱의 Gatekeeper 허용과 실제 실행을 검사했습니다. Windows 배포본에는 Authenticode 서명이 없습니다.

Apple Developer 계정으로 서명·공증한 배포본을 만드는 절차는 [Mac 배포 안내](docs/macos-distribution.md)에 있습니다.

릴리스에는 앱 ZIP과 SHA-256 체크섬을 제공합니다. 업데이트할 때는 기존 앱을 종료한 뒤 새 ZIP을 별도 폴더에 풀어 실행하세요. 앱의 정보 메뉴와 OS 파일 정보에 버전이 표시됩니다. 개발 중인 빌드는 [GitHub Actions](https://github.com/lgyEthan/image_zipper/actions/workflows/build.yml)에서 받을 수 있습니다.

### 소스에서 실행

Python **3.12 이상**을 사용합니다. 의존성 버전은 `pyproject.toml`에 고정되어 있습니다.

Intel Mac에서 소스로 설치할 때는 pikepdf의 네이티브 빌드를 위해 먼저 `brew install qpdf`를 실행합니다. 완성된 앱에는 필요한 라이브러리를 포함하므로 실행 사용자에게 Homebrew를 요구하지 않습니다.

```bash
python -m venv .venv
```

macOS:

```bash
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m image_zipper
```

Windows PowerShell:

```powershell
.venv\Scripts\python.exe -m pip install -e ".[dev]"
.venv\Scripts\python.exe -m image_zipper
```

## 사용 방법

1. 파일이나 폴더를 추가합니다. 목록 순서가 PDF 병합 순서입니다.
2. 사이드바에서 `파일 압축` 또는 `PDF로 합치기`을 선택합니다.
3. `DPI 지정` 또는 `최대 파일 크기`와 출력 형식을 고릅니다. 인쇄 너비·최소 품질은 `세부 설정`에 있습니다.
4. 파일을 선택하면 즉시 추정값이 나옵니다. 실제 바이트 수와 DPI, 압축 후 이미지를 확인하려면 `결과 확인`을 누릅니다. 목록 로딩·파일 선택·설정 변경은 전체 시험 압축을 시작하지 않습니다.
5. 저장 폴더를 고르고 저장합니다. 결과는 `_small` 이름으로 저장하고, 기존 파일이 있으면 번호를 붙입니다.

`최대 용량`은 **개별 저장 시 각 출력 파일**, 병합 시 **최종 PDF 전체**에 적용합니다. 앱의 단위는 MB(1,000,000바이트)입니다. 2 MB는 정확히 2,000,000바이트 이하입니다. CLI의 `--max-mib`는 기존처럼 MiB 단위를 사용합니다. 여러 페이지 TIFF는 페이지 순서와 인쇄 크기를 유지하는 하나의 TIFF로 저장하고, 용량 상한은 전체 파일에 적용합니다. PDF로 합칠 수도 있습니다. 애니메이션이나 다른 다중 프레임 파일은 정지 이미지로 임의 변환하지 않고 중단합니다. 화면의 빠른 미리보기는 첫 페이지이며, 결과 확인은 전체 파일을 계산합니다.

**DPI와 최대 용량은 독립적인 두 모드**입니다. DPI 모드는 지정 해상도로 줄이고, 용량 모드는 프리셋의 DPI와 무관하게 품질과 픽셀 수를 자동 조절합니다. 최소 DPI 제한은 없습니다. 출판 프리셋의 300 DPI를 유지할 수 없는 용량이면 더 낮은 DPI로 저장합니다. 결과 DPI를 함께 표시합니다.

최소 1픽셀까지 줄여도 파일 헤더·ICC 프로파일 또는 PDF의 텍스트·벡터·보존 요소가 상한보다 크면 해당 출력은 저장하지 않고 이유를 표시합니다. 결과와 오류는 앱의 `작업 기록`에 표시합니다. 출력 폴더에는 요청한 이미지/PDF만 저장하며 JSON 보고서를 만들지 않습니다.

압축 속도를 우선해 상한의 약 90% 이상에 도달하면 탐색을 마칩니다. 바이트 수를 끝까지 채우기 위한 반복 압축은 하지 않습니다. 픽셀/품질 단계와 원본 특성 때문에 모든 파일이 같은 크기가 되지는 않습니다. 이미 원본/무손실/최고 품질 결과가 작으면 파일을 불필요하게 부풀리지 않습니다. [성능 검증](docs/performance.md)에 비교 결과를 기록합니다.

### DPI를 해석하는 방법

`DPI = 픽셀 수 / 인쇄 크기(inch)`입니다. 예를 들어 1,800 px 이미지를 6 inch 너비로 인쇄하면 300 DPI입니다. 같은 파일을 3 inch로 인쇄하면 600 DPI입니다.

- 인쇄 너비를 지정하면 종횡비를 유지해 물리적 크기를 정합니다.
- 지정하지 않으면 원본의 가로·세로 DPI를 사용합니다. 회전 이미지에서는 DPI 축도 바꿉니다.
- DPI 정보가 없으면 기본 300 DPI를 **가정**하며, 화면과 결과에 표시합니다.
- 기존 PDF에서는 이미지의 실제 배치 크기, Form 변환, 회전, 재사용 위치, `/UserUnit`을 고려합니다. PDF 페이지 자체에 단일 DPI가 있는 것은 아닙니다.
- 벡터만 있는 PDF에는 DPI를 만들어 붙이지 않습니다. 측정 가능한 이미지가 없다고 표시합니다.
- 확대 보간하지 않으므로 저해상도 원본을 고해상도로 복원하지 않습니다.

### 프리셋

| 프리셋 | DPI 모드 기본값 | DPI 품질 / 용량 모드 최소 품질 | JPEG 방식 |
|---|---:|---:|---|
| 사진 · 인쇄 | 300 | 95 / 90 | 최적화 JPEG, 4:4:4 |
| 도표 · 인쇄 | 600 | 손실 코덱 사용 안 함 | PNG/TIFF 또는 lossless WebP |
| 균형 | 150 | 86 / 76 | Jpegli, 4:2:0 |
| 작은 파일 | 96 | 78 / 60 | Jpegli, 4:2:0 |

용량 모드는 위 DPI나 DPI 모드 품질 상한을 사용하지 않고 최소 품질부터 100까지 조절합니다. 품질 탐색은 최대 네 번이며, 용량이 충분히 가까워지면 더 일찍 멈춥니다. 품질 숫자는 지각 품질 보장 점수나 코덱 간 동등한 척도가 아닙니다. 픽셀까지 보존하는 최적화는 CLI의 `--mode original`을 사용하세요.

## 압축 방식과 경계

구체적인 조사 출처와 선택 근거는 [알고리즘 조사](docs/algorithm-research.md)에 정리했습니다.

- JPEG: **Google Jpegli** 또는 색상 해상도를 줄이지 않는 **4:4:4 JPEG**.
- PNG: **OxiPNG**. 색상 수 감소는 정확히 동일한 픽셀로 표현할 수 있을 때만 수행하며, 투명 픽셀의 숨은 RGB도 임의로 변경하지 않습니다.
- WebP/AVIF: 네이티브 인코더. AVIF는 4:4:4, WebP는 도표 모드에서 lossless.
- 리샘플링: **Lanczos + 정수 축소 최적화**, 반복 인코딩 손상을 피하기 위해 모든 후보를 원본 픽셀에서 생성합니다.
- PDF: pikepdf/qpdf로 스트림 최적화, 내부 이미지의 유효 DPI에 맞춰 선택적으로 리샘플링. 페이지 전체를 이미지로 바꾸지 않습니다. 미리보기만 PDFium으로 렌더링합니다.
- 같은 형식·같은 픽셀 수의 원본이 더 작고 설정을 충족하면 용량/원본 모드에서 원본 바이트를 사용합니다.

**보존을 우선해 변경하지 않는 PDF 이미지**: 마스크·투명도, CMYK/특수 색상, 사용자 Decode 배열, JPEG2000/JBIG2/CCITT, 고비트 심도, 패턴/Type3/주석 내부 이미지, 인라인 이미지 등입니다. 그 결과 지정 DPI보다 높은 이미지가 남거나 용량 상한을 달성하지 못할 수 있으며 이를 표시합니다. 폰트·벡터가 대부분인 파일, 이미 효율적으로 압축된 파일은 큰 폭으로 줄어들지 않을 수 있습니다. 무손실·출판 품질·임의의 작은 용량을 동시에 보장할 수는 없습니다.

**현 버전 범위**:

- HEIC/AVIF는 8비트 SDR 경로입니다. HDR, gain map, depth 정보 보존용 도구가 아닙니다.
- 16비트 회색조 PNG/TIFF는 원본 해상도의 무손실 출력만 지원합니다. 고비트 심도 축소를 요구하면 명시적으로 거부합니다. 모든 16비트 RGB TIFF나 RAW 형식 지원을 의미하지 않습니다.
- CMYK는 자동/TIFF 출력으로 색 공간을 보존합니다. 자동으로 RGB 색 공간으로 바꾸지 않습니다. 투명 이미지를 JPEG로 바꿔 흰 배경을 만드는 변환도 중단합니다. 투명 AVIF 출력은 알파 값을 유지하기 위해 품질 100을 사용하고 필요하면 해상도를 조절합니다.
- 이미지의 ICC, 지원 형식의 표준 EXIF/XMP, JPEG 주석/IPTC, PNG 텍스트·색상 특성, TIFF 설명 태그를 유지합니다. 방향과 픽셀 크기·DPI는 결과에 맞춥니다. 형식마다 고유한 메타데이터나 제조사 보조 데이터까지 완전히 변환하는 도구는 아닙니다. 원본 바이트를 재사용하면 원본 메타데이터도 그대로 유지됩니다.
- 암호화 또는 전자서명된 PDF는 수정하지 않습니다.
- PDF 병합 시 책갈피·양식·첨부 자료 등 문서 전체의 구조를 잃을 수 있는 파일은 중단하고 개별 압축을 안내합니다. 개별 PDF 압축은 이러한 문서 구조와 페이지 내용 스트림을 유지합니다.
- PDF/A·PDF/X 검증이나 출판사 승인 자동 판정은 제공하지 않습니다.
- 용량 탐색은 제한된 횟수의 실측 탐색입니다. 바이트 상한 준수는 검증하지만 수학적으로 최적인 해상도·시각 품질을 보장하지 않습니다.

## CLI

```bash
# 150 DPI로 일괄 저장
image-zipper-cli photos/ -o output/ --dpi 150

# 파일별 최대 2 MiB, 100 mm 인쇄 너비 기준
image-zipper-cli photos/ -o output/ --mode size --max-mib 2 --print-width-mm 100 --format jpeg

# 실제 시험 압축으로 예상값만 확인
image-zipper-cli figure.png --mode size --max-mib 0.5 --estimate

# 입력 순서대로 하나의 PDF. 최종 PDF 전체가 5 MiB 이하여야 저장
image-zipper-cli figure1.png figure2.tif paper.pdf -o output/ --merge combined.pdf --mode size --max-mib 5

# 픽셀까지 보존하는 도표 압축
image-zipper-cli figure.png --mode original --artwork --format png -o output/
```

CLI는 하나라도 실패하면 종료 코드 1을 반환합니다. `--estimate`는 여러 페이지 TIFF와 PDF를 포함해 전체 출력 파일을 계산합니다.

## 개발과 패키징

```bash
python -m pytest -q
python -m ruff check src tests scripts packaging
python scripts/check_privacy.py --history
python scripts/build.py
```

각 OS에서 직접 빌드합니다. `dist/`에 앱과 버전·플랫폼을 명시한 ZIP, SHA-256 체크섬이 생성됩니다. 명시적으로 요청한 개발용 실행 진단은 `build/self-test.txt`에 저장하며 일반 다운로드에 포함하지 않습니다. 기본 자체 검사도 출력 폴더에 보고서를 만들지 않습니다. 완성된 실행 파일을 세 번 실행해 미리보기·시험 압축·저장을 확인합니다. 서드파티 라이선스 텍스트도 번들에 수집합니다. [의존성 안내](docs/dependencies.md)를 참고하세요.

파일 정보는 작업 스레드에서 읽어 목록에 즉시 추가합니다. PNG는 픽셀을 디코딩하지 않고 EXIF를 읽고, 폴더는 점진적으로 탐색합니다. 선택 후 120 ms 디바운스와 최근 12개 미리보기 캐시를 사용합니다. 선택 파일의 작은 원본 해상도 표본으로 DPI 추정을 보정합니다. 미리보기·표본 추정·시험 압축·저장은 별도 프로세스에서 실행합니다. 전체 시험 압축은 버튼을 눌렀을 때만 수행하며, 입력·설정이 같은 저장 작업에서 계산 결과를 재사용합니다. 입력 파일이 바뀌면 다시 계산하고, 앱 종료 시 임시 결과를 정리합니다. 출력은 임시 파일을 완성한 뒤 고유하게 예약한 경로에 교체합니다.

로딩 성능은 `python scripts/benchmark_loading.py sample.png --count 1000`으로 재현할 수 있습니다. 같은 파일의 하드링크를 사용하므로 파일시스템 캐시가 적용된 메타데이터·GUI 처리 성능을 측정합니다. 네트워크/클라우드 파일의 다운로드 속도 측정은 아닙니다.

공개 전 검사에서는 추적 파일·Git 기록·실행 파일의 개인 홈 경로와 자격 증명을 확인합니다. 작성자명과 공증 인증서의 공개 명의는 허용합니다. 보고서에 탐지된 비밀 값 자체를 출력하지 않습니다.
